Mobile-first website quality across real devices.

A responsive site should be readable, operable, quick to open, and stable from a small phone to a large desktop—not merely shrink to fit.

1. Design the layout around content

Use flexible grids, sensible maximum widths, wrapping text, responsive images, and spacing that scales with the viewport. Avoid fixed-width page containers and controls that assume a desktop pointer. Verify headings, cards, product grids, forms, footers, dialogs, and floating tools separately.

A typical layout may use one column on narrow phones, two columns on tablets, and three columns on wide screens. These are examples, not rigid device definitions: content should determine when a layout needs to change.

2. Small phones and accessibility

  • Keep side margins consistent and prevent horizontal page scrolling.
  • Allow long URLs, filenames, and headings to wrap instead of widening the page.
  • Use comfortably sized touch targets, clear focus indicators, and readable line spacing.
  • Stack multi-column forms and keep labels beside their controls.
  • Respect reduced-motion settings and do not depend on animation to communicate meaning.
  • Ensure floating controls do not cover the main action, footer links, or text inputs.

3. Tablets, desktop, and orientation

Test portrait and landscape, narrow laptop windows, zoomed text, browser UI that changes viewport height, and keyboard navigation. Navigation menus must open, close, update their expanded state, and remain reachable by keyboard. Dialogs should fit short screens and allow their content to scroll without trapping the page.

4. Mobile performance

Prioritise the first visible content. Give meaningful images explicit dimensions, lazy-load below-the-fold images, avoid unnecessary large scripts, and limit costly blur and layered shadows on low-power devices. Animation should be lightweight and must not delay the page's primary action.

Do not claim a universal loading time without measurements. Check the site on a real phone and a slower connection, inspect console/network errors, and verify repeated navigation through the service worker after a release.

5. Release checklist

  1. Open every key page at about 320, 360, 390, 430, 768, 1024, and 1440 CSS pixels.
  2. Check portrait, landscape, browser zoom, and a short-height viewport.
  3. Use the full website with touch, keyboard only, and a screen reader where available.
  4. Try forms, navigation, theme controls, speech controls, QR code image loading, and all demo links.
  5. Look for horizontal overflow, clipped text, hidden focus, overlapping floating buttons, and excessive scroll.
  6. Test on a real iPhone/iPad and Android device where possible; emulation is useful but not a replacement.
  7. Deploy to staging or a preview branch first, then verify production assets and cache invalidation.

6. What this guide does not guarantee

Responsive CSS improves layout but cannot guarantee identical browser behaviour across all device models. Voice output, installation prompts, font rendering, keyboard handling, and cached page updates vary with the operating system and browser. Record real findings, fix high-impact issues first, and re-test after changes.
