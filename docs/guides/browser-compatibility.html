Browser compatibility guide

How we make the public website usable across modern mobile and desktop browsers while handling optional features safely.

Our compatibility target

We build with standard HTML, CSS, and browser JavaScript APIs so visitors do not need a special application or browser extension to read company information.

Some enhanced behaviours—native PWA installation, offline caching, and scroll reveals—depend on browser support and permissions.

  • Core content and links remain in HTML.
  • Optional features use feature detection and have a readable fallback.

Progressive enhancement

We treat the page itself as the foundation. JavaScript improves navigation, search filtering, theme controls, and installation help, but it is not the only place where guide names or product routes exist.

When a browser does not expose beforeinstallprompt, we show platform-specific manual installation guidance instead of pretending the native prompt is available.

  • We use IntersectionObserver only for decorative reveals and leave content readable if it is unavailable.
  • We support browsers that expose the older MediaQueryList.addListener interface for system theme changes.

Responsive behaviour

The layout adapts from narrow phones to laptops using flexible grids, sensible line lengths, and responsive navigation. We avoid requiring hover to discover the main action.

Screen width alone does not tell us whether the person uses a keyboard, touch, zoom, or assistive technology, so we keep controls accessible across input methods.

  • We test phone widths, tablet layouts, and desktop content widths.
  • We check focus visibility, text zoom, and navigation when the menu opens or closes.

Known boundaries

A browser, operating system, content blocker, network, or hosting security rule can affect external links and browser-managed installation. Offline access only extends to assets that have been successfully cached.

We do not promise identical rendering, installation prompts, or offline behaviour in every browser version.

  • We document dependencies instead of treating missing browser features as product failures.
  • We retest behaviour after significant browser or hosting changes.

How we confirm support

We check critical routes in current desktop and mobile browsers, then test reduced motion, keyboard input, and offline recovery where the browser supports those features.
