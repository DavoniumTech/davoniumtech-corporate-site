Website delivery and handoff

What we include in a clear website delivery so the owner can find, understand, and maintain the result.

Source and ownership

We provide an organised source structure and keep repository ownership, production branch, hosting account, domain, and DNS responsibility explicit.

A working live URL is not enough on its own; the receiving owner also needs to know where the source and access live.

  • We identify the actual repository and deployed branch.
  • We keep secrets out of public source files and screenshots.

Acceptance checks

We validate the pages and interactions included in the agreed scope: responsive navigation, contact routes, metadata, documentation links, error states, and PWA behaviour where applicable.

A visual review and a functional test are separate checks, and we record any uncompleted validation honestly.

  • We open key routes directly and refresh each route.
  • We check the deployed preview on a phone and desktop before final promotion.

Documentation and support

Our handoff explains how content is organised, how a release is published, how to review a deployment result, and where to report an issue.

The documentation reflects the actual hosting setup rather than a generic workflow copied from another project.

  • We list known limits and third-party dependencies.
  • We explain whether a contact form stores messages or hands them to an external mail app.

Maintenance after delivery

We clarify which updates are included and who will manage future content, releases, domain renewal, and provider settings.

Ongoing monitoring, a service-level agreement, or a managed support queue is not implied unless it is explicitly part of the agreed service.

  • We keep rollback steps available for significant updates.
  • We update handoff notes when repository or deployment ownership changes.

Handoff complete

We record which files were delivered, who owns the accounts, how the site is deployed, and which follow-up tasks remain with us or the client.
