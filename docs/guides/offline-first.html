Offline-first design principles

How we provide useful offline recovery without promising that uncached pages or external services work without a connection.

What offline means here

Our website can reopen selected pages and assets after the service worker has installed and those resources have been cached successfully. This is a useful fallback for a previously visited site, not a complete offline copy of the internet.

On first use, the browser must connect to our website before it can download the service worker and initial cache.

  • Core shell resources are cached first.
  • Other pages can enter the cache after a successful online visit.

Cache design

We keep the first cache operation small so a large documentation library does not block service-worker installation. Optional page caching is allowed to fail without cancelling the installation of the essential shell.

We version cache names when the shell changes so older resources can be replaced deliberately.

  • We cache same-origin content and avoid pretending that external resources are local.
  • We respond with the offline page when an uncached network request cannot be completed.

Data and user expectations

The browser manages the stored cache and may remove it under storage pressure or when the visitor clears site data. Offline support does not preserve account data or submit a form in the background.

Contact email, WhatsApp, and external product links still need the relevant app or network.

  • We explain which page is unavailable instead of showing a false success state.
  • We do not store form messages in the service-worker cache.

How we test it

We first open important routes while online, wait for service-worker activation, then test a refresh and repeat visit with the network disabled. We also test a genuinely uncached route to verify the recovery message.

A test on one browser is not proof that every browser uses identical cache limits or offline behaviour.

  • We check cache version changes after releases.
  • We keep recovery links and core styles available in the essential shell.

Offline verification

We test offline use only after the service worker has activated and the relevant page has been cached from a successful online visit.
