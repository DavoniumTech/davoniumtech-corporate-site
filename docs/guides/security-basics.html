Website security basics

The security boundaries we use for public static websites and how we avoid overstating what those controls protect.

Security model for this site

Our company website is primarily public static content. It does not provide a website account database or a server-side ticket system through the contact form. That reduces some risks but does not remove the need for secure hosting and careful releases.

We use HTTPS through our hosting provider and keep secrets out of public HTML, JavaScript, and Git history.

  • We review the source before production changes.
  • We treat the contact email and external services as separate systems with their own controls.

Access and deployment

We keep source and hosting access under company-controlled accounts and review which branch publishes production. A successful local test or Git push is not a substitute for checking the resulting deployment.

We use a backup commit or branch for significant changes and inspect the hosting logs when a deployment fails.

  • We avoid force-pushing over shared history.
  • We never put API tokens, service-account keys, passwords, or recovery codes in this repository.

Browser and site protections

We keep dependencies minimal, validate links, use a custom error page, and respect browser security boundaries. Our website does not pretend to secure a server-side endpoint that it does not have.

Any future login, payment, upload, or data API would need its own threat model, authorization rules, rate limits, logging, and incident response.

  • We test forms honestly and do not claim a static mailto form stores tickets.
  • We apply bot challenges selectively rather than blocking every human visitor behind a long delay.

Reporting and limitations

We welcome responsible reports about exposed information or unexpected behaviour. We investigate based on reproducible details and the affected public route.

This guide is a practical overview, not a certification or a claim that every possible vulnerability has been eliminated.

  • Report the page, steps, observed result, and expected result.
  • Do not include credentials or exploit other users while demonstrating a concern.

Security scope

Our site is a static website, not a complete account or payment backend. If we introduce authenticated or data-handling endpoints, we will document and test their separate controls.
