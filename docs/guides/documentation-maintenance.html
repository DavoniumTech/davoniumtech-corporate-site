Documentation guide

Documentation maintenance

How we keep public guides specific, searchable, accessible, and aligned with the actual company website and products.

How we organise our guides

We publish documentation as standalone HTML pages with direct links, descriptive titles, canonical URLs, and a searchable index. Each guide has a clear subject and content written for that subject.

The search control filters the list in the browser; it is not the only way to reach a guide. All guide links are already present in the page markup.

  • We group guides by the reader’s task: products, engineering, PWA behaviour, search, privacy, and support.
  • We link related guides so readers can continue without returning to the homepage.

Our editorial ownership

We write documentation in Davonium Technologies’ own voice. When a guide describes our decisions, we use “we” and “our”; when it explains external browser behaviour, we name the platform and state the limitation.

We remove placeholder copy and template language that tells us what we ought to do instead of explaining how we actually work.

  • We verify company and product statuses against the current public pages.
  • We avoid claiming that an unbuilt feature is already available.

Search and accessibility

Every public guide is reachable through an ordinary anchor with a real href, even when JavaScript is unavailable. Page content is not generated solely by a search interaction.

We maintain an XML sitemap and public crawler guidance to support discovery, but search engines determine which URLs they index.

  • We check internal links, headings, metadata, and mobile readability.
  • We test the search empty state and the Clear action.

Review cycle

We update a guide when behaviour, product status, a vendor platform, or a material company decision changes. A review date is an editorial signal, not a substitute for testing or legal review.

We treat privacy, terms, and browser-storage policy pages as drafts until they have been checked against production data practices and applicable requirements.

  • We correct inaccuracies when we find them.
  • We keep deployment-only notes in source documentation rather than public customer guides.

Keeping this library useful

We update or retire guides when product behaviour, file paths, support routes, or hosting behaviour changes. We avoid adding pages that merely repeat existing information.
