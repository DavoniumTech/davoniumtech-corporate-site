Error pages and recovery paths

How we help visitors recover from missing routes, interrupted connections, and unavailable offline resources.

When something fails

We design error states to explain what happened in plain language and provide a useful next step. A visitor who reaches a missing page can return to the homepage or open the products and support sections.

A clear 404 response is preferable to displaying a normal-looking homepage for a route that does not exist.

  • Our Cloudflare configuration uses the custom 404.html page for missing assets.
  • Our offline page explains when a requested resource is not available in the local cache.

How we recover

We offer ordinary links to the homepage, products, documentation, and contact page so recovery does not depend on browser history or JavaScript alone.

We make the error and offline routes independent from network-only resources as far as the static design allows.

  • We keep recovery links simple and descriptive.
  • We avoid claiming that an offline page can retrieve content the device has never cached.

Testing failure paths

We test direct access to valid pages, an invalid route, offline reopening after a successful visit, and the return to a normal online page.

A broken navigation link and a valid route that is temporarily unavailable are different problems; our diagnostic steps distinguish them.

  • We inspect HTTP response and Cloudflare logs when a route fails.
  • We test clean URLs as well as source .html files where redirects apply.

Known limits

A first-time offline visit cannot download missing content. External product links, WhatsApp, and email handoff also depend on a network or a configured external application.

We state these limits plainly so we make the difference between cached content and connected services clear.

  • We keep the offline message helpful rather than alarming.
  • We update route links when the hosting model changes.

Recovery path

When a route fails, we direct visitors to the homepage, documentation, or support page without implying that a missing page is temporarily available.
