Route and link reliability

We design our public website so a visitor can reach company pages, product information, the five core demos, documentation, and contact options without being trapped in redirects or a blank error page.

Release rule

One URL policy must be used across the hosting configuration, links, canonical tags, sitemap, and offline cache. Mixing two opposing redirect policies can create a loop.

1. Canonical route policy

This deployment uses Cloudflare HTML handling with automatic trailing-slash behaviour. A page stored as page.html should be linked and indexed at its canonical extensionless path, such as /page. Directory landing pages use a trailing slash, such as /demos/. Our _redirects file intentionally contains comments only: it must not redirect /page to /page.html when the host redirects /page.html back to /page.

2. How we check routes

  1. Confirm the real HTML file exists in the repository.
  2. Resolve every local link relative to its source page and check that the target exists.
  3. Check in-page anchors, canonical tags, structured data and sitemap URLs.
  4. Test clean paths such as /about, /products, /services, /demos/ and each of the five core sample pages.
  5. Inspect the host response chain and make sure a request does not bounce between an extensionless path and a .html path.

3. Cache and offline behaviour

The service worker cache name is versioned for each route repair. When routing or important layout code changes, the cache version must change so updated pages and assets can replace older ones. Offline mode is a best-effort fallback for pages that have already been cached. It cannot make a network failure appear as a real successful response, and it cannot guarantee that contact delivery, browser speech, remote services, or every interaction works offline.

4. Responsive and accessible navigation

All navigation controls must remain reachable by touch and keyboard, work at narrow viewport widths, respect device safe areas, and avoid placing the floating DVNM Bot over important content. During speech playback, the interface focuses on the robot and exposes a clear Cancel Speech control. Reduced-motion preferences must be honoured.

5. Sample and product accuracy

The five core DVNM Biz, DVNM Market, DVNM Creative, DVNM Skills and DVNM Digital pages are sample website demonstrations created by Davonium Technologies. They illustrate design and interaction directions; they are not claims of client commissioning or live commercial service. The patterns are intended for organisations and audiences worldwide and can be adapted for market, language, currency, accessibility, and operational requirements.

6. Release acceptance

  • There are no active extensionless-to-.html redirects that conflict with Cloudflare HTML handling.
  • Every local HTML reference points to a real file or canonical directory route.
  • The sitemap and canonical URLs follow the same path policy.
  • JavaScript and service-worker syntax checks pass.
  • All five core demo pages, the PDF showcase record, and QR images remain in the output bundle.
  • The deployed site is checked separately from the local files; a successful Git push alone is not a deployment confirmation.
