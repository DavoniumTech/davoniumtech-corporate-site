Release notes and change history

How we record meaningful website changes, bug fixes, compatibility updates, and known limitations.

What we record

We use release notes to describe changes that matter to visitors: route fixes, responsive adjustments, installation behaviour, offline handling, product status, and documentation updates.

A good note explains the user-visible impact instead of simply naming a commit or repeating an internal task title.

  • We identify the affected area and the outcome of the change.
  • We distinguish a fixed issue from a known limitation.

How we describe evidence

We record what was actually tested. Static syntax checks, HTML validation, a preview test, and a real-device test prove different things, so we do not report them as equivalent.

When a test has not been performed, we state that rather than implying a full QA sign-off.

  • We include relevant route or browser conditions when they matter.
  • We do not claim performance gains without comparable measurements.

Compatibility and risk

For changes involving the service worker, manifest, route handling, or storage keys, we explain how existing visitors may receive the update and what they may need to refresh.

A cached page can temporarily behave differently from a freshly loaded release, so PWA changes need repeat-visit testing as well as a first-load check.

  • We note material changes to routes and offline cache names.
  • We identify any migration or manual reset that a visitor actually needs.

Public change history

We keep the public changelog focused on outcomes and the repository history focused on implementation details. We keep the public changelog and repository history consistent with each other.

We update product status and public docs whenever a release changes what people can access.

  • We remove obsolete release instructions.
  • We keep known limitations specific and actionable.

Release history

We keep public release notes concise and evidence-based. We distinguish changes that have shipped from work that remains in development.
