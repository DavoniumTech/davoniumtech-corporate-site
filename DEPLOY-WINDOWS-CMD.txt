1) BACK UP AND PREPARE

Open Windows CMD. Adjust the Downloads path if you saved this ZIP elsewhere:

cd /d "%USERPROFILE%\Downloads"
powershell -NoProfile -ExecutionPolicy Bypass -Command "Expand-Archive -LiteralPath '%USERPROFILE%\Downloads\davoniumtech-corporate-site-DVNM-Bot-Demo-Studio-20261021.zip' -DestinationPath '%USERPROFILE%\Downloads\davoniumtech-corporate-site-DVNM-Bot-Demo-Studio-20261021' -Force"

The extracted folder contains the website root. Confirm index.html exists:

dir "%USERPROFILE%\Downloads\davoniumtech-corporate-site-DVNM-Bot-Demo-Studio-20261021\davoniumtech-corporate-site-main\index.html"

Open your EXISTING local repository folder (do not make a new repo):

cd /d "%USERPROFILE%\Downloads\davoniumtech-corporate-site-deploy"
git remote -v
git status
git fetch origin
git switch main
git pull --ff-only origin main

Confirm origin is https://github.com/DavoniumTech/davoniumtech-corporate-site.git. If `git status` shows local changes that you need, stop and back them up before copying.

3) COPY THE UPDATED WEBSITE SAFELY

Replace the source-folder path below if you extracted somewhere else. The destination must be your existing repository folder. `/E` copies new and updated files but does not delete unrelated files; do NOT use `/MIR`.

robocopy "%USERPROFILE%\Downloads\davoniumtech-corporate-site-DVNM-Bot-Demo-Studio-20261021\davoniumtech-corporate-site-main" "%USERPROFILE%\Downloads\davoniumtech-corporate-site-deploy" /E /XD .git

echo Robocopy exit code: %ERRORLEVEL%

Robocopy exit codes 0–7 usually indicate a successful copy; 8 or higher indicates a failure. Check the target folder before continuing. If the extracted folder name differs, use `dir` to locate the actual index.html and adapt the path.

This repository controls the corporate website, not necessarily the separate `ready2go.davoniumtech.com` host. The updated corporate pages remove its direct links, but users may still reach the separate host if it is independently deployed and public. To actually block access, add a Cloudflare Access gate/redirect or disable/restrict the Ready2Go deployment and test the subdomain separately. `robots.txt` and hidden links are not security controls. Do not announce the app is inaccessible until the subdomain itself has been tested.
